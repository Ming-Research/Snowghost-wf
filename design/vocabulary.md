Decision: The document is an arena: its nodes live in one `Box<Slots<Node>>` named by `NodeId`, a `u32` index, with parent, first and last child and sibling links held as indices, because Whitefoot never stores a reference, so a tree is either owned or linked by indices, and the parser, the HTML tree construction rules and script need to reach any node by its identity and to insert, move and remove nodes anywhere, which an owned tree cannot give, instead of an owned tree of nodes.

Decision: Layout lengths are `LayoutUnit`, an `i32` counting 1/64 of a CSS pixel, with the geometry types built on it, because fixed point adds and compares exactly, keeps a layout independent of floating-point rounding and evaluation order, and still spans about 33 million pixels, as Blink's layout unit does, instead of `f32` or `f64` lengths; a computed length stays `f32` CSS pixels and is truncated toward zero to `LayoutUnit` once, when layout reads it, and a text fragment's width is the sum of its glyphs' unrounded advances in logical order rounded up once, both as the reference does ([rounding](../research/investigations/layout/DESIGN.md#interface-choices)) rather than rounding each glyph's advance, which drifts by up to 1/128 px a glyph and moves line breaks, because percentages and `calc()` with them already wait for layout's containing block, so layout reads every computed length anyway, and the stage's oracle reports computed lengths unrounded ([style](../research/investigations/style/DESIGN.md#choices-after-the-results)), instead of rounding at computed-value time.

Decision: Tag, attribute and property names are atoms, `u32` indices into one atom table in which every name the renderer knows has a fixed index generated ahead of time, because matching, the cascade and tree construction compare names on every element and an atom turns each comparison into an integer comparison and each known name into a constant, instead of comparing name bytes or hashes at each use.

Decision: A document's character data lives in one UTF-8 byte arena per document, named by `u32` spans, because every stage but script reads UTF-8 and the HTML and CSS preprocessing rules already replace what UTF-8 cannot encode; how a lone surrogate that script stores is kept is decided when script lands, with WTF-8, as Servo stores DOM strings, the expected candidate, instead of UTF-16 text, which every stage but script would convert.

Decision: An element's computed style is a small struct of group identifiers, one per group of values that change together and that one layout step reads: box (display, position, float, clear, overflow, box-sizing, visibility, z-index), size and offsets, margins and paddings, border, font, text, background, custom properties, flex and grid container, flex and grid item, table, and generated content, with variable-length values such as track lists and content lists held as spans into side stores, each group interned in its own table, because equal styles then share storage, a style comparison compares identifiers and inheritance copies one, and the tables are independent, so each is interned as its own task in parallel, instead of a full computed style per element, one sequential interning pass over all groups, or the layout-only properties added to the box group, where values most elements leave initial would make box groups differ and lose sharing; provisionally, because whether interning stays within the bound of 15 percent of the four-worker style stage, which a single sequential pass reached after matching gained its rule index ([style measurement](../research/investigations/concurrency/DESIGN.md#style-measurement)), and how often each group's values are shared are measured on the real stage, which may split a group or partition a table by hash; on the real stage three runs put interning at 10 to 22 percent of the four-worker stage on ecma262 and html5 and under 8 percent on apollo11, on both sides of the bound ([style results](../research/investigations/style/DESIGN.md#criterion-2-speed)), so it stays provisional until interning alone is timed.

Decision: A computed length that depends on a percentage, alone or mixed with a length in `calc()`, stays a percentage and an offset until layout resolves it against its basis, because the containing block's size is layout's result, so resolving it in the style stage would make style depend on layout, against CSS's definition of computed values, which `computedStyleMap()` reports as the stage's oracle, instead of resolving percentages against an assumed containing block.

Rejected:
- An owned document tree: rejected because the tree construction rules move and reparent nodes (the adoption agency and foster parenting) and script holds node identities, neither of which an owned tree expresses without stored references.
- UTF-16 document text: rejected because only script reads UTF-16, while tokenizing, matching, shaping and line breaking read UTF-8.
