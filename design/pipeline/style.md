Decision: The style stage matches each element in one counted loop over the elements in document order, each iteration reading only the document and the rule store and writing its own element's matched rules, and then cascades and inherits in one pass in document order, because matching is 65 percent of style's work and depends on no other element's result, while an element's cascade depends only on its parent's, which document order already places first; this shape was the fastest of the three measured, 0.790 s at four workers against 0.810 s for level order and 1.107 s for halving the preorder (median of three real pages, [style measurement](../research/investigations/concurrency/DESIGN.md#style-measurement)), instead of level-order storage or recursion that halves each sibling run.

Decision: Matching tests an element only against the rules its own id, class words and local name select through an index of each rule's rightmost compound, plus the rules whose rightmost compound names none of them, and reads each element's sibling positions from one table built before matching, because a rule whose rightmost compound names another id, class or type cannot match, so the matched rules are unchanged, while testing every rule cost 590 tests per element and counting siblings at every `:nth-child` test cost time in proportion to the element's position; the two brought style at four workers from 0.696 to 0.224 s on ecma262, 0.942 to 0.180 s on html5 and 0.416 to 0.202 s on apollo11 ([rule index and sibling positions](../research/investigations/concurrency/DESIGN.md#styles-work-per-element)), instead of testing every rule and counting siblings per test.

Rejected:
- Level-order storage, one counted loop per tree level: rejected because it was 2.5 percent slower than matching in document order at four workers and needs a second order map for every consumer that reads styles in document order.
- Recursion that halves each sibling run in document order: rejected because the runtime's fixed recursion budget runs out under the wide sibling runs of real pages, leaving apollo11 at 1.11 times its sequential time at four workers.
- Cascading per formatting context: rejected because the pipeline keeps no unit of parallel work, and an element's cascade depends on its parent, not on its formatting context.
