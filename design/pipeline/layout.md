Decision: Layout stores an owned tree of formatting contexts, each holding its block boxes and paragraphs in flow order and owning its child contexts in `Box<Slots<Context>>`, with every paragraph broken into lines in one counted loop before the context's block pass places floats and breaks again only the paragraphs a float narrows, because the block pass is layout's only chain of true dependencies, which made layout at four workers 3.31 and 2.94 times faster than the sequential build on html5 and apollo11, whose largest contexts hold floats, and a context's child contexts depend only on their element and width; provisionally for static rendering, since whether the context is also the unit of memoization and invalidation is decided by the first incremental prototype ([open question](../research/investigations/concurrency/DESIGN.md#open-question-the-unit-of-storage-invalidation-and-caching)), instead of per-stage arrays indexed by element.

Decision: The box tree is built by one walk of the document in tree order that records each paragraph's text as pieces, byte spans of text nodes and single inserted scalar values, followed by one counted loop that decodes and collapses each paragraph's pieces into its text, because only the order of the flow is a chain, while a paragraph's text depends on its own pieces alone, instead of decoding and collapsing text during the walk.

Rejected:
- Decoding text during the walk: rejected because it keeps four fifths of the builder's work, turning text into scalar values, inside the walk's chain.
