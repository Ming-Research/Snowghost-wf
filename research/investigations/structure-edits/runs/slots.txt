Implementation
--------------
- renderer/style/module.wfm:structure_restyle has the requested signature
  and effect row. Exactly one inserted/removed option is required. Full
  requests the caller's full path; structural is True for these edits.
- renderer/style/structure.wf:structure_restyle, append_element and
  append_style_node append only the inserted subtree's rows. Parent slots
  supply depths. The restyle set is new elements plus structural_restyle's
  NodeIds mapped through order; the existing restyle level frontier runs
  into the kept tables. Every inserted slot is returned as changed.
- Removal clears both order maps to 4294967295 and traversal.elements and
  cascade.nodes entries to NodeId(4294967295). Removed pseudo rows become
  tombstones; their original sorted-list positions are preserved.
  renderer/layout/build.wf:build_boxes skips traversal holes.
- renderer/style/structure.wf:element_node maps an original element to its
  original node slot and an appended element to element slot plus the
  original pseudo count. No appended pseudo rows are accepted; such an
  insertion takes the permitted full fallback. Original pseudo indices
  therefore never move on the retained path.
- renderer/style/incremental.wf:restyle, restyle_level, style_at and
  place_style use the element/node distinction. inherited.wf and levels.wf
  test cascade.kinds rather than element_count for node kind. The level
  cascade keeps its existing counted-loop and disjoint-write form.
- renderer/style/traversal.wf:filled_slots replaces retained fixed Array
  allocations with Slots, preserving full-build indices, lengths and values.
  It reserves 4096 extra entries. This changes allocation code and is not
  proof of worst-case local growth; see the first gap below.
- renderer/css/selectors/positions.wf:children_changed updates only the
  edited parent's original children's sibling positions/totals, using
  sparse namespace/name counters. The first linked-child pass supplies
  ranks/totals and the second publishes totals. The sequential dependencies
  are the next sibling link and preceding same-type/element counts.
  Newly appended NodeIds use sibling scans. Original class records remain
  usable after arena growth; new NodeIds cannot overwrite those records.
- renderer/oracle/layout/edit.wf:apply_structure_edit times the retained
  style operation as style_us. structure_flags allocates the temporary
  NodeId-indexed Bool array and marks changed live elements and every
  detached subtree node. This O(nodes) allocation is charged to delta_us.
  The full helper includes the time spent attempting the retained path.
- structure_changed reads old generated bytes and pseudo identity, not an
  old snapshot of all computed values. The kept tables preserve references,
  generated-byte prefixes and pseudo indices; changed flags cover the live
  style changes. The kept Styles can therefore serve as both old and new.
  No old-Styles copy is made (copy cost: zero). Removed nodes are absent
  from both order views and ignored by changed_outside; their boxes are in
  the context rebuilt for their former parent. retained_outside recognizes
  a tombstoned pseudo owner without moving any other pseudo reference.
- renderer/oracle/layout/edit.wf:build_page preserves the kept traversal
  while producing the full comparator. layout.wf:write_dump builds a
  canonical traversal only for untimed output and resolves styles by NodeId.
  Neither traversal rebuild is on the edittime retained style path.
- renderer/oracle/style/structure.wf:run_structure checks live membership,
  slot holes/inverse maps and computed element/pseudo values against a fresh
  full computation per NodeId after every B/X. Values use the existing
  complete style-dump serialization (including its float formatting), not
  raw floating-point bit equality or internal custom-property table identity.
- incremental-layout/scripts/inctime.py validates/counts explicit structural
  style fallback records without weakening existing edit, count or DIFF checks.

Interface, locality and completion gaps (priority order)
-------------------------------------------------------
1. Strict worst-case locality and literally unchanged full-build code are
   NOT delivered. Runtime Array is fixed-size and has no append/conversion;
   retained rows use Slots. The allocation code changes, although full
   output identity holds. The 4096-entry reserve delays allocation copies;
   unbounded appending can still copy an O(elements) allocation. A bounded
   growth representation is needed before claiming the absolute guarantee.
   Existing intern-table growth is also not a new worst-case-local proof.
2. The packed Positions cache is not fully appendable. Original siblings
   are updated per parent, but new NodeIds use uncached sibling/class scans.
   Wide-sibling and allocation-growth-boundary behavior was not measured.
3. class_restyle still consumes preorder ranges. With traversal.stale it
   requests a full build after B/X. The canonical dump also needs preorder,
   but runs outside the timed edit path. Mixed B/X/C/K sessions have not been
   validated here; replacing that class reach remains necessary for E2.
4. The given immutable RuleStore interface cannot register newly inserted
   inline declarations/presentational hints. Minimal example: append
   <p style="color:red"> after loading the store. B creates a plain p, so
   the measured scripts do not cover this gap. A store preparation/update
   operation is needed before general insertion with new declarations.
5. The sparse list for newly appended pseudos was not implemented. The
   explicitly allowed insertion fallback is used. General multi-element
   inserted subtrees and reinsertion of a previously detached subtree were
   not exercised by the supplied B/X scripts.
6. Layout still allocates the O(nodes) Bool delta and performs its existing
   O(context) structural work. These are the explicitly deferred M2 steps
   3/4, not costs eliminated by this change. No old-Styles snapshot cost is
   added. Full-build speed and repeated-run timing uncertainty remain open.

The first four gaps and reopening conditions are maintained in docs/todo.md
under stable-slot boundaries and inserted declarations. No design-tree
change or silent replacement of Q108/Q110/Q111 is claimed. The full-build
allocation deviation and worst-case growth limit remain unresolved against
the requested contract; this report is not a claim that all of M2 is done.
