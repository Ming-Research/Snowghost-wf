Flow-relative properties in the first page-by-page comparison with Chromium
(2026-10-13)

Source: the first page-by-page layout comparison of the 21 web-app pages of
the test set (CI run 38351929419 on the research/parity-pagewise branch),
against Chromium 141.0.7390.37 through Playwright 1.56.0 on Ubuntu 24.04,
1280x720 viewport, with the snapshots of run 38310399089. The audit took, on
each page, at most 15 block-level boxes that mismatch while their parent or
every earlier sibling matches (183 boxes in all) and attributed each by
reading the page's style sheets and Snowghost's source at 6a13652.

Ignored flow-relative padding, margins, borders and insets were the primary
cause of 14 of those boxes, on six pages: proton-mail, trello-home,
threads-zuck, ikea-billy, apple-tv and vimeo-watch. Their subtrees and later
siblings hold about 377 mismatched block boxes; this is an exposure bound,
not the number the mapping fixes. Examples:

  proton-mail  a header child 1280 px wide where Chromium has 1152 px
               inset by 64 px: the header's `padding-inline: 4rem` (64 px
               on each side) is ignored.
  trello-home  a column 8 px shorter than Chromium's: `p { margin-block-end:
               1.5rem }` is ignored, so the 16 px default bottom margin
               stays instead of 24 px.
  trello-home  a paragraph 24 px lower than Chromium's: `h1 { margin-block:
               0 .5rem }` is ignored, leaving a 32 px default bottom margin
               instead of 8 px.

Snowghost's longhand list at that revision named only the physical
properties, so every logical declaration was dropped at parse time.
