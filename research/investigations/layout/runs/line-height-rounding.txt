Line-height as a layout unit (Chromium, headless)

Probe: a div with `font: 14.08px sans-serif` and one line "x", `line-height` set per div; the div's
height is the line-height as the reference makes a LayoutUnit (1/64 px) of it.

  line-height   value in 1/64 px   Chromium   truncated   nearest
  21.12px       1351.68            21.125     21.109375   21.125
  19.2px        1228.80            19.203125  19.1875     19.203125
  16.1px        1030.40            16.09375   16.09375    16.09375
  20.01px       1280.64            20.015625  20          20.015625
  18.003px      1152.19            18         18          18
  17.7px        1132.80            17.703125  17.6875     17.703125
  17.5px        1120.00            17.5       17.5        17.5
  1.5           (21.12 px)         21.109375  21.109375   21.125

A line-height given as a length is rounded to the nearest layout unit, where every other
computed length is truncated (design/vocabulary: Q54); a number is in the second table. The rows of apollo11's infobox are 21.125 px of
line plus 2 px of padding in Chromium and a unit shorter here, 1 px after 60 rows.

A number line-height, probed with `font: SIZEpx/NUMBER sans-serif` (div heights; the product is
in 1/64 px):

  14.4   1.625     922               1498.25                          1498
  14.08  1.5       901               1351.5                           1351
  16     1.2       1024              1228.8                           1228
  13.5   1.4       864               1209.6                           1209
  12.6   1.3       806               1047.8                           1047
  15.2   1.625     973               1581.1                           1581
  14.4   1.6       922               1475.2                           1475
  11.2   1.5       717               1075.5                           1075
  17.6   1.5       1126              1689.0                           1689

The font size is rounded to the nearest layout unit and the product with the number truncated
(Blink keeps a number as a percentage and multiplies it by the font size as a LayoutUnit), which
fits all nine; truncating size * number directly (the rule here before) misses 14.4 * 1.625 and
15.2 * 1.625.
