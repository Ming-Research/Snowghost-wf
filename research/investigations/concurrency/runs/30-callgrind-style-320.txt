Question and prior expectation
------------------------------
With one fixed Snowghost source and pinned ecma262 inputs, how does #320's
header-only Slots construction change compute_styles Ir? The expectation
supplied before collecting was that memset under match_complex nearly vanishes;
unchanged substantial attributed memset would reject that expectation.

Method
------
The sequential build is run.sh's build_layout command with separate output
names. runs/11-callgrind-style-58fa8ee.txt identifies proto_layout_seq and
collection limited to compute_styles, but neither it nor run.sh records the
old callgrind CLI. Both v0.119 drivers inline compute_styles into
wf_proto.layout.drive.resume. The wrapper's only body call, style_shape_c,
remains as a direct call; there is no call to the retained compute_styles
symbol. Collection by that symbol (and by *compute_styles*) therefore yielded
zero, and those profiles are excluded. Disassembly and the diagnostic full
profile establish the surviving call. The final collector names style_shape_c.
The numbers below are this body inclusive; any inlined wrapper/result handling
in drive.resume is outside the measured region.
L1 0 parses and prepares the same input, computes styles once (shape C with
the current rule index and sibling positions), builds the layout tree and
runs no layout repetitions. Collection starts on entry to style_shape_c and
stops on return from that body. Wrapper/result handling and the layout setup
after return are outside the measured region.
Runs interleave before-1, after-1, before-2, after-2 on one GitHub-hosted runner.
No wall-clock timing was collected; these are instruction counts, not speedups.

Commands (repository root, hosted Ubuntu runner only)
----------------------------------------------------
make toolchain RELEASE=wf-f3d081b90a8d
make compiler RELEASE=wf-ef4a73b56044
sudo apt-get update
sudo apt-get install -y valgrind
root=$PWD
data=build/research/concurrency
ua=research/investigations/concurrency/ua.css
mkdir -p "$data" build/style-320 build/style-320-counts
sed -n '/^ecma262.* https:/p' research/investigations/concurrency/run.sh > build/style-320/input-pins.txt
while read -r name url sum; do
  curl -fsSL --retry 3 -o "$data/$name" "$url"
  echo "$sum  $data/$name" | sha256sum -c -
done < build/style-320/input-pins.txt
for pair in before:wf-f3d081b90a8d after:wf-ef4a73b56044; do
  side=${pair%%:*}
  release=${pair#*:}
  compiler="$root/build/whitefoot/$release/whitefootc"
  (cd renderer && "$compiler" --cache "$root/build/whitefoot-cache" --fragments function --graph modules.wfg --entry proto_layout -o "../build/style-320/proto_layout_seq-$side")
done
for side in before after; do
  objdump -d --disassemble=wf_proto.style.compute_styles "build/style-320/proto_layout_seq-$side"
  objdump -d --disassemble=wf_proto.layout.drive.resume "build/style-320/proto_layout_seq-$side"
done
for repeat in 1 2; do
  for side in before after; do
    WF_WORKERS=1 valgrind --tool=callgrind --collect-atstart=no --toggle-collect=wf_proto.style.style_shape_c --callgrind-out-file="build/style-320-counts/callgrind-$side-$repeat.out" "build/style-320/proto_layout_seq-$side" L1 0 "$data/ecma262.html" "$ua" "$data/ecma262-ecmarkup.css" "$data/ecma262-print.css"
    callgrind_annotate --auto=no --threshold=100 --inclusive=no "build/style-320-counts/callgrind-$side-$repeat.out"
    callgrind_annotate --auto=no --threshold=100 --inclusive=yes "build/style-320-counts/callgrind-$side-$repeat.out"
    callgrind_annotate --auto=no --threshold=100 --inclusive=yes --tree=caller "build/style-320-counts/callgrind-$side-$repeat.out"
  done
done
