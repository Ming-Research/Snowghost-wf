# W8 — one owned event array per pass

HYPOTHETICAL: C1/C2 for tree facts and indexed reads. The scratch allocation itself
is **today's** `Box<Array<Event>>`, not an unmentioned region primitive. It is
filled with a valid Gap value, then completely overwritten before any walker
uses it. This deliberately exposes the extra initialization and release costs.

Source lines: 53. Original: `fill_flow` and `materialize_flow` in
`renderer/layout/sequence.wf`, plus `place_context` in
`renderer/layout/flow.wf` (3,515 lines). The original already materializes once
for a context pass; this proposal does not claim to invent that optimization.

```wf
fn fill_events(scene: &Scene, part: TreePart, destination: &[Event]) -> result: unit reads(scene.entries), reads(scene.payloads), writes(destination) contract {
  requires tree_part_for(part, scene);
  requires destination^.len == part.events;
  ensures events_for(destination, part, scene);
} {
  let split = tree_split(scene: scene, part: part);
  match split {
    Empty() => {
      return unit;
    }
    Node(left: left_part, entry_key: key, own: own_part, right: right_part) => {
      let left_end = left_part.events;
      let own_count = entry_event_count(scene: scene, key: key);
      let own_end = left_end + own_count;
      let count = destination^.len;
      fill_events(scene: scene, part: left_part, destination: &destination^[0_u64..left_end]);
      fill_events(scene: scene, part: right_part, destination: &destination^[own_end..count]);
      let item = scene^.entries[key].item;
      match item {
        Block(key: block) => {
          let inside_start = left_end + 1_u64;
          let close_at = own_end - 1_u64;
          set destination^[left_end] = Event::Open(key: block);
          fill_events(scene: scene, part: own_part, destination: &destination^[inside_start..close_at]);
          set destination^[close_at] = Event::Close(key: block);
        }
        Text(key: paragraph) => {
          set destination^[left_end] = Event::Text(key: paragraph);
        }
        Child(key: child) => {
          set destination^[left_end] = Event::Child(key: child);
        }
      }
      return unit;
    }
  }
}

fn context_pass(scene: &Scene) -> result: PassResult reads(scene) contract {
  requires scene_valid(scene);
  requires summaries_ready(scene);
} {
  let part = root_part(scene: scene);
  let count = part.events;
  let empty = Event::Gap();
  let events = box_array_filled::<Event>(count: count, value: empty);
  fill_events(scene: scene, part: part, destination: &events.inner[0_u64..count]);
  let placed = placement_walk(scene: scene, events: &events.inner[0_u64..count]);
  let hit_boxes = hit_walk(scene: scene, events: &events.inner[0_u64..count]);
  let inspected = inspection_walk(scene: scene, events: &events.inner[0_u64..count]);
  let made = PassResult(placed: move placed, hit_boxes: move hit_boxes, inspected: move inspected);
  return move made;
}
```

The weight invariant proves `left.events + own_count + right.events == len`,
with all values fitting u64. A leaf has `own_count == 1`; a block has
`own_count == own_part.events + 2`. These facts give every addition/subtraction,
subscript and range formation its domain, including an empty nested block.
Left, own and right output ranges are disjoint; block Open, inside and Close
are disjoint within the own range. Exact event completeness is a constructor
postcondition proved by this structural recursion. It is not inferred from
having allocated an Array or from the absence of a crash.

PAR-1 may overlap the left/right/own fills; their only writes are to separated
ranges. Scene is read-only during materialization. `placement_walk`, `hit_walk`
and `inspection_walk` all receive one call-local borrow of the same immutable
events; their outputs are separately owned. Their private walk stacks evolve
in event order because Open/Close changes the current owner transform; independent
walks need no ordering against each other. They return owned output lists, never
references to scratch. The event array drops after the pass, and cannot escape
inside `PassResult` through REF-3. No kernel region or lifetime exception is used.

The retained tree keeps structural weights, not a cached flattened event array,
so a later edit pays only for the next pass that actually asks to materialize.
Cost: `O(events)` allocation/initial fill plus `O(events)` real fill; one event
array allocation/release per pass; several read walks. Multiple ancillary arrays
still allocate separately. A general arena could reduce that constant, but the
mocks do not assume it is free or needed for independence. Eliminating Gap fill
without permitting uninitialized reads requires a separate split-and-seal
construction facility (or a proved no-fill lowering), recorded as F3.
