# W6 — private build, injective publication, targeted retirement

HYPOTHETICAL: C1/C2. `build_private` uses W5's builder and preparation on an
isolated unpublished store. Successful private construction has packed fresh
entry/payload domains (no retirement or slot reuse); this is a general builder
postcondition, not a special path for one document. A more general sparse source
requires an explicit key map, charged in F1.

`preflight_splice` validates the supported seam, all representational/arithmetic
limits, changed summary bounds and every external attachment before mutation.
After successful reservations the remaining operations are total under these
requirements; they contain no partial-return error path. Heap exhaustion follows
STOR-8. The owning library temporarily opens the Scene invariant while fields
are relocated, using **store-local** live/vacant predicates and the immutable
Rebase, not the temporarily false complete-scene predicate. No observer runs
until the operation returns. This is exclusive publication, not an atomic
transaction with concurrent readers or a crash-recovery guarantee.

`private_payload_key` and `private_entry_key` read immutable packed domain
metadata and compute keys; their rows exclude the source payload contents being
extracted. Extract writes one header/value, not a global source length. The
Rebase describes the immutable **old identity domain**, so it survives source
extraction; it never claims those source cells are still live. `emplace` changes
one reserved destination, not a shared destination append boundary. Thus the
two publication loops each have distinct source and destination footprints.
Private and retained stores are distinct roots. Retained old payloads do not move.

`rewrite_payload` changes every identity-bearing field of its owned argument:
entry back-link, parent owner, block index root, summary's entry handles, paragraph
Object pieces (the body above), marks/atomics and context anchors as present in
the production record. `rewrite_entry` changes owner, target, all parent/child
index links and entry handles in leaf/total summaries. Non-key input/geometry
fields keep their meaning; only newly attached root origins get the seam offset.
Child contexts keep their own internally scoped key domains. Each wrapper's row
writes only its owned argument and reads Rebase; its traversals are counted loops
over its own arrays/stores like the shown Object-piece loop. An omitted identity
field is a correctness bug, not something C1 infers from a field's name.

`stage_inputs` reserves and fills the new input-domain records before payload
extraction; each independent destination is the matching mapped payload key.
It uses the same checked remap for parent links and source-style references.
`close_splice` retires only removed input records. These are data moves, with
linear new/removed-input work, and use disjoint cells after reservation.

`publish_seam` splices the mapped direct-root index into the owner and detaches
the removed roots, using AVL split/join and local backlink repair. It updates
only touched external routes and paragraph census membership. Paragraph census changes use the checked batch algorithm in design.md, including
parallel compaction of removal holes and surviving tail keys. A repeated
swap-removal loop is not the proposed batch implementation. New paragraph
key-buffer capacity is reserved before independent fills; its count changes once
after filling. The removal lists were collected while
the old tree still existed and are distinct. They remain valid for retirement
of their named cells even though they cease to be reachable from the published
root. Retirement loops read only immutable lists, not the backlinks in the other
retirement domain. No free-list push or shared counter is in either loop.
`close_splice` seals the final forest/index/inverse predicates and returns the
boundary change for W2's propagation after the direct seam has settled.

Real order: source preparation precedes relocation; reservation precedes writes
to its cells; publication waits for all initialized targets and rewritten links;
detachment precedes retirement; semantic ancestor repair depends on seam output.
The two domain-copy loops could overlap because their data supports are disjoint;
the source text need not join them early. The Object-piece loop is independent
by its direct slot map and only writes its own Piece. Costs include `O(new
records + embedded references + removed records)` work, destination page/header
allocation, and one move of each **fresh** payload. For large embedded piece
lists that reference child contexts, rebasing is not constant-time page adoption.
