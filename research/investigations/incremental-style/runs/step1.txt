M1 step 1: the style stage's value tables kept in Styles (Q89, Q92 for the
list tables), filled by a full build from empty tables. Every command ran
from the repository root on an Apple M1 Pro (macOS), Whitefoot pinned at
3629be153, under the host lock for builds and timings.

Sources
  Main: 732b602 (a detached worktree). M1: the commit that adds this
  record. Both style_oracle builds carry the same oracle change, which
  prints in mode `all` the sizes of every table of Styles (the eleven
  groups, the custom sets, the list tables and the generated text) in
  place of the first seven groups and the custom sets alone.

What changed
  The seven hashed groups keep an open-addressing index beside their table
  in Styles, grown to twice what the table can hold after a call and
  rebuilt by value when it grows; the item, table, container and content
  groups keep their word tables (WordTable, grown by doubling within
  word_ceiling) and their list tables. A full build passes them empty, so
  identifiers are the insertion order of today's per-run tables and every
  output must be byte for byte main's. The custom-property sets stay per
  run: their identifier is the first set of the run's Inherited store with
  the same entries, and a kept form needs the inherited pass's own store
  kept (step 3).

  the second call grows the index with entries in it. Table sizes and the
  html5 and style-cases style dumps equal main's.

  cannot see a lost identifier, the table sizes do.
