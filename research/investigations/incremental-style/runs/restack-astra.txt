Dependencies and candidates
---------------------------
Stacking has a true ordered dependency through collapsed margins, floats,
open frames and cursor. Replaying an unchanged prefix recomputes already
known state and adds no new information. Retaining complete state at sparse
flow positions would bound that replay without adding an order between
contexts or paragraphs. Reconstructing state from ancestor blocks and a
preceding settled entry may avoid retained snapshots if all inputs can be
recovered exactly. A summary tree could shorten more of the stacking chain
but changes every position reader and exceeds this investigation unless
the simpler candidates prove inadequate. Fragment preservation must retain
the exact full-build geometry and ordering, including split inline boxes.

This required report lives with incremental-style run records and remains
as the evidence for this experiment; scratch logs and binaries live in build/.

Initial implementation experiment
---------------------------------
The one-block cutoff excludes nested changed blocks, even when every block
keeps its horizontal geometry. Record their common ancestor through the
existing parent links, validate widths throughout that block, and restack
through its closing entry before permitting convergence. This adds only
ancestor dependencies to marking and the affected block's validation; it
removes the unnecessary dependency on the rest of the context's pre-pass.
Compare identical font-size scripts against base and require byte identity.
For this first variant, if the affected range cannot preserve horizontal
geometry or includes marked child contexts, retain the existing full path. A preceding placed paragraph
can subsequently bound replay. No snapshot storage is added.

Implementation and dependency argument
--------------------------------------
No persistent checkpoints and no module-interface changes were added.

1. mark_use records the common ancestor of changed blocks, using preorder
   IDs and parent links. Its chain is only the two ancestor chains. A fully
   restyled context skips this work. restack_block verifies every dirty
   paragraph lies within that subtree and refuses marked child contexts.
   It visits the subtree through its close before permitting convergence.
2. Width checks are a counted reduction independent of the ordered flow
   boundary scan. If widths change in a block-and-text-only subtree, an
   immutable copy of those blocks lets each block, paragraph and split
   record recompute its own ancestor widths independently. This duplicates
   ancestor arithmetic rather than ordering siblings. Child contexts,
   atomics and columns retain the full path.
3. stack_flow finds the preceding unchanged paragraph with lines by
   paragraph order. Its natural position plus height restores the cursor;
   its parent chain restores the open frames, and preceding placed floats
   restore exclusions, floor and reach in existing flow order. Pending
   margins are empty after a paragraph with lines. Coordinate saturation
   rejects inversion before any block geometry is mutated, then the
   ordinary prefix replay runs. No added shared cache orders paragraphs.
4. Suffix floors are lazy, needed only when float geometry and a changed
   stacking state require the conservative convergence check. Split
   rectangles are rebuilt; empty-inline fragments can be retained when
   paragraph line presence and horizontal inputs have not changed. With
   no splits, the own box and retained empty rectangles suffice. Empty
   paragraphs have no placed lines and retain their origin in full layout.
5. A local width change also compares broken_width and broken_left before
   keeping line breaks, and marks definite_free false if the changed block
   range introduces a relative height dependency.

Choices Q1 (affected block range and independent local widths) and Q2
(reconstructed restart state and guarded empty-fragment retention) are
provisional in design/pipeline/layout.md. Owner approval remains open; the final acceptance failure below prevents

The alternatives are the existing full pre-pass and persistent sparse
