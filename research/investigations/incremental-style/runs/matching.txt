Matching cost of a restyle and of the full style stage
======================================================

Question: what dominates a class edit's restyle after step 4, and how much of
it can rule selection remove without changing a matched rule?

Criterion, written before measuring: the following changes are kept only if
the full style dumps of the three pages are byte-identical to the base, the
incremental style and layout identity checks pass, and a deliberately broken
variant fails those dumps. Each change is kept only if it lowers the median
restyle of apollo11's toggle script.

Environment: Apple M1 Pro, macOS 26.6.2, Whitefoot c3d26643c, sequential
build unless marked par. Builds used `--cache --fragments function`. The
machine was shared with other agents' compiler builds (load average 6-10).
The full-stage figures are pairs of runs, and differences under 5 percent
are noise.

Base: 84c1bf1 (build/m1/prefilter_style_seq).
Result: f9c5bfe (build/m1/style_seq).

Workloads
---------
- toggle: build/m1/scripts/apollo11-toggle.edits, 60000 C/K toggles of class
  x5c on node 1138 against `.x5c{color:#123456}`. Mode restyletime gives the
  restyle_us median. Every edit follows the previous one directly, so the
  cache is warm.
- full: `style_oracle all 3` on each page, wall seconds.
- E1: research/investigations/incremental-layout/run.sh time BUILD PAGE KIND 1,
  "style+update us" median. Each edit follows a full-layout comparison, so
  the restyle runs with a cold cache.

Profile of the base toggle (sample, top of stack)
-------------------------------------------------
- Matching was 55 percent of active samples: instr_matches, match_complex,
  backtrack and class_records.
- gather_reaches was 7-10 percent. It is a linear scan of every class reach.
- memset inside match_complex zeroed its 64-frame backtracking stack once
  per tested alternative.

--------
- Style dumps of apollo11, html5 and ecma262 are byte-identical to the base.
- Incremental style check: every script reports 0 differ:

  - html5 and ecma262: classes, sclasses, body, custom, scolour, scustom.

- WPT dom/nodes selectors (css_selectors_oracle): 356 cases, 356 passed,

Review finding: sibling combinators (fixed after the review)
------------------------------------------------------------
The review of 45340e7 found that alternative_mask required every compound
left of any descendant or child combinator as an ancestor feature, including
one followed by a sibling combinator, which matches a sibling of an ancestor.
`.a + .b .c`, `.a + .b > .d`, `.x ~ .y .z` matched nothing with the filter
(the reviewer's page: span, i and b black instead of red, blue, green). No
page selector of that shape matched on the three pages and WPT's selector
cases call the matcher without the filter, so every check above passed.

Fix: a compound is an ancestor feature only when its own right-hand
combinator is a descendant or child combinator. On the review's page plus
`.p > .q + .r .s` (an ancestor left of a sibling combinator), the fixed
build's dump equals the build before the filter byte for byte; the build at
45340e7 is the falsifier. The cases are in tests/css/style-cases.html; their
Chromium comparison is unverified on this machine (no Playwright module).

Per-alternative items isolated (filter in both builds; all 3, seconds, two
runs each): apollo11 0.76/0.74 -> 0.39/0.37, html5 2.77/2.77 -> 1.52/1.52,
ecma262 3.92/3.93 -> 2.87/2.89.
