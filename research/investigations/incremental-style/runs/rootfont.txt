Root font-size edits without a rematch
======================================

Question: a root font-size class edit makes restyle rebuild every node
(rebuild_all), including matching every element again. Can the rebuild keep
the cascade instead?

The restyle has already rematched the restyle set. The reverse index puts
every element whose matched rules change into that set (step 2). So the
kept cascade holds every element's winners, and only the inherited and
reset passes and the interning depend on the root font size.

Criterion, written before measuring: keep the change only if the style
oracle's incremental check (a full style run after each edit) reports 0
differ on the root font-size scripts and the incremental layout check
reports inc same on them.

Environment: Apple M1 Pro, Whitefoot c3d26643c, sequential build, machine
shared with other agents. Base: 29f059a. Result: the commit carrying this
file.

Style oracle incremental mode, restyle_us median (cold; full style between
edits)

  html5 srootfont (10 edits)     483447 -> 184974  differ 0 / 0

What is left:

- The inherited and reset passes and the interning over every node.
  - A root font-size change reaches only the nodes that read the root's
    font size through inheritance or a rem length.
  - A record of the rem readers would let the level restyle replace the
    rebuild.
- The layout update. It is already below a full layout (html5 610 against
  about 785 ms, ecma262 453 against about 700 ms), but it alone exceeds
  Chromium's whole edit on ecma262.

Root font-size readers and box-only changes
-------------------------------------------
Two measurements found where the rest of the time went. On ecma262 a root
font-size edit changed only 18 elements in what layout reads. Body sets
18px, so only html, head's subtree and #spec-container{max-width:80rem}
read the root's size. Even so:

- the layout update prepared and shaped 45,931 paragraphs again, because a
  use records its paragraphs as one range and the range between the root's
  first and last reader spans the page;
- the style stage rebuilt every node.

Changes:

1. Paragraph marking tests each paragraph of the range. Its pieces are
   always tested. Its strut is tested only when the element's font, text,
   table or content values changed; restyle reports the other case with
   changed_boxes_only.
   Falsifier: ignoring the pieces makes apollo11 fontsize edit 1 DIFF.
2. A root font-size change no longer rebuilds by default. The levels start
   again with the elements whose winning declarations can read the root
   size queued at their depths. Those are:
   - a length with a rem part;
   - a var() value whose text, or some custom property's value, holds a
     rem dimension;
   - a track list or border spacing.
   It rebuilds without matching when the readers, or the elements visited,
   pass one sixty-fourth of the elements (one sixteenth at first; html5 then wasted about 12 ms of levels before rebuilding). The changes the levels found before
   that are added to the rebuild's list, since they already wrote those
   styles; leaving them out made html5 srootfont edit 1 DIFF.
   Falsifier: ignoring rem lengths makes ecma262 srootfont differ at
   #spec-container.

Style oracle incremental check: 0 differ on every script, the rootfont ones
included. Layout identity: every script of the suite reports inc same, with
DIFF 0 and refused 0.
