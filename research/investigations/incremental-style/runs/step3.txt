M1 step 3: the partial passes on a kept style state (Q89, Q91's inherited
frontier, Q92), checked against a full style run after every edit. Host,
compiler and inputs of runs/step1.txt; style oracle built sequentially from
the commit that adds this record.

What was added
  intern_values interns any list of styled nodes into the tables Styles
  keeps (17b795a; dumps, table sizes and full-build time unchanged, the
  eleven intern calls still adjacent in the --par ledger).
  pkg::style::style_state keeps the rule indexes, the three parts' results
  and each element's pseudo-elements; pkg::style::restyle, given a class
  edit's restyle set (runs/step2.txt):
    - matches the set's elements and their pseudo-elements again, each
      clearing and refilling its own winner row;
    - then, one tree level at a time from the set's shallowest element,
      computes again the set's elements of that level and the queued ones
      (inherit_element, the reset pass's two functions for the node, and
      interning the level's nodes and their pseudo-elements into the kept
      tables), and queues the element children of every element that is in
      the set, whose inherited values or custom-property set changed, or
      whose computed style changed;
    - rebuilds every node instead, still into the kept tables, when an
      element of the set gains or loses a pseudo-element or the root's font
      size changes.
  The levels, and the nodes within a level, run sequentially in this step;
  the level loop that the full build proves parallel (inherit_level) is not
  used yet.
  The style oracle's mode `incremental` (run.sh incremental) compares, after
  every C and K edit, the restyled styles with compute_styles of the edited
  document, line by line as the dump writes them.

2. Falsifiers, each built separately and required to fail
  F1 the reaches other than the edited element ignored (class_restyle
     keeps reach_self only): apollo11 body, 9 of 26 edits differ.
  F2 the inherited cutoff taken while the custom-property set changed: a
     first version that only compared the inherited values and not the set
     never failed (custom, 0 of 26), because a changed set also changes
     each element's custom identifier and a changed style queues the
     children too; with that second path also blind to the custom
     identifier, apollo11 custom fails, 3 of 26 edits, the first with 844
     elements differing. The cutoff has two paths and the check fails only
     when both are wrong.

3. What the counts show for step 4 and 5
  A colour or font-size class edit visits the edited element and its
  children (the children because explicit inherit and blockification read
  their parent's declarations): at most 103 elements on html5.
  A root font-size edit always rebuilds, since rem lengths anywhere read
  the root's font size: criterion 2's root font case needs the nodes whose
  values read rem or the root, not a rebuild.
  A custom-property change reaches every element's custom identifier
  (changed = visited), which layout does not read: the sparse interface of
  step 4 has to report what changed per group, not only that something
  did.
